# MyPicsDB 3 0.2.20: deferred date refresh

## Problem

The background service detected a local date change and immediately called
`ReloadSkin()` when Estuary MyPicsDB 3 was open on the Home window. In the
reported Kodi log this happened within the same second as a scheduled video
library scan. Kodi unloaded and rebuilt the complete skin while the scanner and
home widgets were also active, after which the log stopped.

`ReloadSkin()` is intentionally retained because Estuary's plugin-backed Home
rows cache their directory contents. A normal `Container.Refresh` does not
reliably rebuild those rows.

## Change

The service now queues the date-sensitive refresh and waits 60 seconds before
the first attempt. The request stays pending until it can be completed.

For Estuary MyPicsDB 3, a skin reload is allowed only when:

- the Home window is active;
- no Kodi library scan is running;
- no media is playing;
- no modal dialog is active;
- the screen saver is inactive;
- DPMS is inactive.

An unsafe attempt is retried after 15 seconds. Transient exceptions are logged
and retried instead of stopping the background service. Other skins keep using
`Container.Refresh`.

## Database impact

None. Schema version remains 3.

## Verification

Coverage includes:

- an idle Home-window reload;
- deferral for every unsafe Kodi condition;
- deferral while another window is active;
- the 60-second grace period;
- retry after an unsafe attempt;
- retry after a transient exception.
