# 0.8.29 whole-library metadata reindex

Version 0.8.29 adds an explicit **Refresh all picture metadata** action under
**Browse metadata**. It exists to update old catalogue rows after extractor fixes such
as the 0.8.26 Kodi VFS byte-stream correction and 0.8.27 XMP/GPS compatibility work.

## Behaviour

- Operates only on already-indexed still pictures; videos are skipped.
- Does not traverse source folders, discover media, mark missing rows or rebuild sources.
- Re-reads EXIF/XMP/IPTC with current settings/mapping rules and refreshes canonical
  fields, tags, search text and affected folder summaries.
- Runs serially under the existing `metadata-refresh` writer lock.
- Can be cancelled and later resumed from `metadata-refresh-all-v1.json` in the local
  Kodi add-on profile. The checkpoint contains counters/IDs only, not source paths or
  metadata values.
- Freezes a maximum picture-ID horizon when the run starts; pictures added later are
  left for normal scanning or a future full refresh.
- Does not perform online reverse geocoding. Existing 0.8.28 provider+coordinate cache
  entries may be reused locally without network I/O.

## Compatibility

- Plug-in: 0.8.29
- Database schema: 9 (unchanged)
- Query Model: 1 (unchanged)
- Scanner remains serial; no parallel file I/O is added.
- No Estuary revision is required.
