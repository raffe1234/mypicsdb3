# Patch 0.2.22: optional video indexing and mixed slideshows

## Scope

This patch adds a deliberately limited first video layer to MyPicsDB 3. It keeps
the useful MyPicsDB2 approach: pictures and videos share the catalogue and Kodi
remains responsible for playback. Video indexing is opt-in and does not add a
separate scraper or an external `ffprobe` dependency.

## Database

Schema 4 adds `pictures.media_type` with the default value `picture` and an
`idx_pictures_media_type` index. SQLite databases are backed up by the existing
migration runner before the column is added. MySQL/MariaDB uses the same
migration history and lock discipline. Existing rows remain pictures.

## Scanner

- Picture extensions continue through EXIF/IPTC/XMP extraction.
- Enabled video extensions are stored as `media_type=video`.
- Video date initially falls back to file modification time.
- Video MIME type is inferred from the filename.
- Disabling video support and scanning marks previously indexed videos missing.

## Browsing and playback

Videos participate in folder, recent, date, favorites and search results.
Camera, keyword, geolocation and embedded-rating views remain picture-only. A
dedicated Videos node is available when video indexing is enabled.

Mixed slideshows are built from catalogue rows and sent to Kodi picture playlist
2 with JSON-RPC `Playlist.Clear`, `Playlist.Add` and `Player.Open`. Album
playback can include descendants. Playback is capped at 5,000 items per action.

## Deferred work

- Container metadata such as duration, dimensions and embedded creation date.
- Generated thumbnails on Kodi versions or skins that do not expose them.
- A media-neutral table rename; the existing `pictures` table remains for
  compatibility.
- Video-specific ratings and tags.
