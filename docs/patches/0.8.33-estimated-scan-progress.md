# 0.8.33 — estimated scan progress

Manual and automatic scans previously kept their background progress bar at zero
through discovery. They now show approximate percentage, checked files, newly
indexed files and estimated minutes remaining, using a matching complete-scan
reference rather than an extra NAS traversal.

The first error-free complete scan after upgrading establishes a per-source count
in the existing catalogue meta table. References are keyed by source and validated
against source URI and effective scan policy. Unavailable, cancelled, partial or
erroring source runs do not replace a good reference. Missing or malformed history
and history I/O failures do not prevent indexing.

Progress aggregates selected sources and restored checkpoint work. Current-session
rate estimation starts after ten active seconds and ten checked files; it excludes
playback pauses and work from before resume. New-file counts refer to successful
catalogue inserts, not all discovered candidates. The saved folder checkpoint
remains the authority for counters restored after an interruption.

At or beyond the old count, the UI explicitly says it is still scanning and stops
showing percentage/ETA. A successful return from the scanner is the only completion
signal. Unknown estimates reset the numeric background bar and explain the state
in text. Directory progress is reported before removing the folder from the pending
stack. Cancellation and lock loss during listing propagate without being swallowed
as ordinary directory errors.

No schema migration, metadata extractor revision, repository/screensaver version or
Estuary patch revision change is needed. Counts and estimates never determine scan
selection, stopping, checkpoint compatibility or missing-record marking.

## Kodi acceptance before tagging

1. Finish one complete scan to establish the matching source references.
2. Start another scan of the same sources/settings; confirm the approximate bar,
   new-file counter and time-left display after sufficient active processing.
3. Pause via playback, resume, and exercise Stop scan / resume. The rate should
   exclude the pause and pre-resume work; counts should not double-count sources.
4. Include a newly added file. Check that reaching the old count switches to the
   still-scanning message and does not end discovery early.
5. Wait for green CI/build checks and verify the installed version is 0.8.33 before
   creating the v0.8.33 release tag.
