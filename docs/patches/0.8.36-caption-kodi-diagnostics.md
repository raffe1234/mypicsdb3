# 0.8.36 — Kodi caption exposure and resilient metadata diagnostics

## Purpose

Make the caption corrected in 0.8.35 directly verifiable in Kodi and prevent a fresh
metadata-reader compatibility failure from making **Metadata diagnostics** unusable.

## Kodi picture metadata boundary

Kodi documents picture EXIF keys for `ListItem.setInfo`, but current Kodi accepts only
resolution and capture date through the Python picture metadata path. Camera make/model
and caption/comment compatibility keys are rejected, while `InfoTagPicture` exposes no
Python setter for IPTC Caption. MyPicsDB 3 therefore:

- keeps resolution and capture date on `InfoTagPicture`;
- stops sending the unsupported camera/comment compatibility keys;
- keeps camera text on `MyPicsDB3.Camera`; and
- publishes canonical caption as the new stable `MyPicsDB3.Caption` list-item property
  for regular picture results and native slideshow rows.

## Metadata diagnostics

- Show **Caption** under both **Indexed values** and **Fresh extraction**.
- Read the indexed catalogue row first. If fresh extraction raises, keep the dialog
  open with the indexed values and display the exception under Fresh extraction instead
  of replacing the entire dialog with an error notification.
- Log the exception class and message for maintainers without requiring the user to run
  a second diagnostic workflow.
- Treat optional `xbmcvfs.translatePath` / legacy `xbmc.translatePath` hooks as callable
  only when they actually are callable. This removes one plausible `NoneType` callable
  failure on compatibility VFS shims.

## Compatibility

No database migration or re-index is required. Database schema 9, Query Model 1,
metadata extractor revision 2, repository version 0.2.26, screensaver version 0.7.0
and the read-only source-file boundary are unchanged.

## Validation

Regression coverage verifies Caption list-item publication, Caption in successful
diagnostics, graceful indexed-only diagnostics after a fresh-extraction failure and
non-callable `translatePath` compatibility hooks. Run the normal repository tests,
`tools/verify.py` and the add-on checker before release.
