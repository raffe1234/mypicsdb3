# 0.8.15 stale scan recovery

Version 0.8.15 is a robustness release prompted by a real Kodi hard-stop during a
very large schema-9 metadata reindex. The process died before normal scanner
cleanup, leaving both the catalogue scan lock and a `scan_runs` row in `running`
state. Restarting Kodi could therefore report a scan as running while every new
manual or automatic scan was rejected as overlapping.

## Behaviour

- SQLite scan owners already contain hostname, process id and a random token. A
  new scanner may remove a stale SQLite `catalogue-scan` lock only when it was
  created on the same host by a different Kodi process and that recorded process
  is confirmed absent. A live, same-process or uncertain lock is preserved and
  left to the normal TTL path.
- MariaDB/MySQL never performs this early process-based recovery. The catalogue
  can be shared by several Kodi devices, so lock heartbeat and TTL remain the
  source of truth.
- After a scanner acquires exclusive ownership, older `scan_runs` rows still
  marked `running` are finalized as `interrupted` with a finish timestamp before
  a new source run begins.
- When the automatic service encounters a valid competing lock, it retries after
  60 seconds rather than postponing the attempt for the full configured scan
  interval.

The database schema remains 9 and Query Model remains version 1. No source media
is modified and no checkpoint semantics change.

## Safety reasoning

The order matters: do not mark old runs interrupted before exclusive scan
ownership has been obtained. For a shared backend, an apparently old run may
still belong to another live client. Likewise, do not extend SQLite's local
process-owner shortcut to MariaDB/MySQL.

## Regression coverage

Tests cover recovery of a prior-process SQLite lock, preservation of a lock owned
by the current Kodi process, conversion of the orphaned scan-run row to
`interrupted`, and the 60-second automatic busy retry. Existing lock-refresh,
checkpoint, cancellation and MariaDB integration tests remain authoritative.
