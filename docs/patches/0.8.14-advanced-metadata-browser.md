# 0.8.14 advanced metadata browser

Version 0.8.14 implements the next verified legacy-parity step while keeping database
schema 9 and Query Model version 1.

## User-visible changes

- Add **Browse metadata** to the add-on main menu.
- Group indexed metadata into Camera, Location, Capture, Image and Keywords.
- Show bounded picture counts for camera make/model, country/state/city/sublocation,
  capture year, file extension, MIME type, image shape, rating and keyword values.
- Paginate long metadata value lists and open selected values as normal Query Model
  picture results.

## Architecture and safety

Legacy MyPicsDB could enumerate arbitrary stored tag types. MyPicsDB 3 does not copy
that raw-tag architecture. The browser owns a curated metadata definition; the
catalogue owns a fixed aggregate-expression allowlist; and selected values are
translated into already-supported Query Model v1 rules. No file metadata name is an
SQL identifier and no source media is read by the browser.

`query_facet_counts()` gains offset-aware pagination and new portable facets, including
a normalized keyword join and an orientation-aware aspect CASE expression. SQLite
and opt-in MariaDB tests cover the expanded aggregate surface.

## Scan-performance note

This release intentionally does not parallelize the scanner. Large first scans and
schema-9 metadata reindexes can be slow because each eligible picture's metadata must
be inspected once, especially across SMB/NFS. Current serial processing preserves Kodi
VFS behaviour, a single ordered write stream, cancellation, scan-lock refresh and
folder checkpoints. A future optimization should first benchmark a small bounded worker
pool for read/metadata work while keeping catalogue/checkpoint commits serial.
