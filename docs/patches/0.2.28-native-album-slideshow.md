# MyPicsDB 3 0.2.28: native album slideshow

## Problem

MyPicsDB 3 built album slideshows as a database-backed Kodi picture playlist.
A background monitor then watched for indexed videos and advanced the picture
playlist when video playback ended. On some Kodi 22/CoreELEC systems, recursive
slideshows could stutter and Kodi could restart after several pictures.

Disabling the monitor was not a usable fix. Kodi then opened still JPEG files in
VideoPlayer as short MJPEG streams, so they finished almost immediately and a
sequence containing several files was difficult to stop.

Kodi's normal **Pictures > View slideshow** path played the same SMB album,
pictures and videos correctly.

## Change

Starting a slideshow from an indexed album tree now calls Kodi's native
recursive folder slideshow:

```text
SlideShow("<album folder>",recursive,notrandom)
```

Kodi therefore owns the picture timing, video playback, consecutive-video
transitions and stop handling for album slideshows. The folder URI is quoted
without changing the underlying media URI.

Database result sets that may span unrelated folders continue to use the
existing JSON-RPC picture playlist and video monitor.

## Compatibility

- Database schema remains version 4.
- Repository add-on version remains 0.2.26.
- Scanning, metadata and catalogue queries are unchanged.
- Album slideshow order remains non-random unless Kodi's slideshow controls are
  used to change it.

## Verification

Automated coverage checks the native recursive built-in call from an album and
the lower-level slideshow helper. Manual testing covered pictures, videos,
consecutive videos and stopping playback from an SMB album.
