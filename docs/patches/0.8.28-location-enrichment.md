# 0.8.28 explicit online location enrichment

Version 0.8.28 adds privacy-gated reverse geocoding on top of the offline GPS/XMP
foundation from 0.8.22-0.8.27. It deliberately supports one user-selected picture at
a time and does not create an automatic or bulk geocoding workflow.

## Behaviour

- **Online reverse geocoding** is disabled by default.
- **Resolve location online** appears only when a still picture has a valid stored GPS
  pair. Invocation asks for confirmation before network I/O.
- The request sends only latitude/longitude plus fixed Nominatim API parameters. Image
  bytes, filename, SMB/NFS URI and catalogue IDs are not sent.
- The default endpoint is `https://nominatim.openstreetmap.org`; the base URL is an
  advanced setting so a compatible service can be switched without an add-on update.
- Requests identify MyPicsDB 3 with a dedicated User-Agent and use `geocodejson`
  address details. Returned attribution is stored/displayed. Cache misses are spaced
  by at least 1.1 seconds using a persistent per-endpoint timestamp.
- Provider+coordinate results are cached in schema-9 `meta`; repeated explicit lookup
  of the same coordinate/provider does not contact the service again.
- Resolved country/state/city/sublocation fill only canonical fields that are empty.
  Embedded EXIF/XMP/IPTC values keep precedence, and the global-search document is
  refreshed transactionally.
- A `location-enrichment` lock conflicts with scan, migration and metadata refresh. A
  busy catalogue blocks the action before the HTTP request.
- Explicit metadata refresh and later changed-file/forced scanner reads reapply saved
  enrichment when fresh embedded location metadata remains absent; neither path makes
  a provider request.

## Public Nominatim policy boundary

The public OpenStreetMap Nominatim service is capacity-limited. Its current usage
policy requires an identifying User-Agent/Referer, attribution and caching, imposes an
absolute maximum of one request per second, and discourages periodic/bulk geocoding.
0.8.28 therefore enforces at least 1.1 seconds between provider cache misses and
provides no folder, recursive, scanner-triggered or scheduled online lookup. If future
requirements become bulk-oriented, use a provider/self-hosted service designed for
that workload instead of expanding the public endpoint path.
