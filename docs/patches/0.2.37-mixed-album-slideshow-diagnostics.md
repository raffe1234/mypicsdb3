# MyPicsDB 3 0.2.37: mixed album slideshow and diagnostics

## Scope

Kodi's native recursive `SlideShow` remains the preferred path for album trees
that contain only pictures. When the indexed album tree contains at least one
video, MyPicsDB now builds the same bounded picture playlist used by database
results and arms the scoped mixed-video monitor only after `Player.Open`
succeeds.

This keeps picture-only playback native while avoiding reliance on platform- or
version-specific native handling of videos inside a picture slideshow. The
playlist remains capped by the existing 5,000-item action limit.

## Diagnostics

The add-on's **Debug logging** switch now emits opt-in diagnostics at Kodi INFO
level, because Kodi otherwise hides `LOGDEBUG` messages unless global debug
logging is enabled. No separate add-on log file is created. Diagnostics include:

- selected slideshow route and scope;
- picture/video, empty and duplicate counts;
- bounded `Playlist.Add` batches and `Player.Open`;
- mixed-monitor activation, indexed-video detection and idle cleanup.

Media URIs are not written by the new diagnostics.

## Kodi checks

1. Enable **Debug logging** in MyPicsDB 3, without enabling Kodi global debug.
2. Start a picture-only album tree and confirm `route=native-picture` in
   `kodi.log`.
3. Start an album tree containing video and confirm `route=mixed-playlist`,
   non-zero video count, playlist batches and monitor activation.
4. Verify picture-to-video and video-to-picture transitions, stop behaviour and
   Kodi shutdown.
5. Repeat on the platform where native mixed album playback already worked to
   ensure the explicit mixed route does not regress playback.
