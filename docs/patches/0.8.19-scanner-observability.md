# 0.8.19 — Scanner observability

This release deliberately measures scan performance before introducing any
parallel file processing. The scanner remains serial on Kodi VFS, SQLite and
shared MariaDB.

## What is measured

- eligible media discovered;
- unchanged catalogue rows;
- picture metadata reads;
- added and updated rows;
- missing rows marked and errors;
- wall-clock files/second;
- aggregate directory-listing time;
- aggregate file-stat time;
- aggregate picture metadata-inspection time.

The live **Scan status** screen exposes rate and counters. At scan completion a
single privacy-safe log summary records totals and timing buckets without media
paths or credentials. Resumable checkpoints retain the counters so a continued
scan does not silently reset the measurements.

## Safety boundary

No ThreadPoolExecutor or worker queue is added. Traversal, stat calls, metadata
reads, catalogue writes, commits, checkpoint advancement, missing detection and
lock ownership retain their existing order. The instrumentation adds monotonic
clock reads and counters only; it does not intentionally perform additional NAS
I/O. Any future bounded parallel-read design should be justified by these
measurements and tested separately on real Kodi/SMB workloads.
