# 0.8.24 EXIF resilience and diagnostics viewer

Version 0.8.24 is a focused metadata hotfix discovered through the 0.8.23
**Metadata diagnostics** action. Kodi's picture-info dialog could show Camera Make
and Model while MyPicsDB Fresh extraction returned zero EXIF tags and an
`UnicodeDecodeError` from ExifRead.

## Behaviour

- ExifRead remains the primary EXIF parser.
- If ExifRead raises, MyPicsDB parses only the embedded TIFF/EXIF container already
  present in the configured metadata prefix.
- The fallback recovers Make, Model, orientation, DateTime/DateTimeOriginal/
  DateTimeDigitized, EXIF width/height, Rating/XPKeywords where structurally safe,
  and GPS latitude/longitude/reference fields.
- MakerNote and UserComment are intentionally ignored, so a broken free-form text
  tag cannot prevent recovery of unrelated core fields.
- Source files remain read-only; no network service or reverse geocoding is used.
- Existing indexed rows are not silently rewritten on upgrade. Use explicit refresh
  after diagnostics confirms that Fresh extraction now succeeds.

## Diagnostics UI

The diagnostics report now uses Kodi's `Dialog.textviewer` when available, making
long reports scrollable and substantially larger than the previous OK dialog. A
small OK-dialog fallback remains for compatibility. The report also states whether
the core EXIF fallback was used and how many fallback tags were recovered.

## Compatibility

Database schema remains 9 and Query Model remains version 1. Scanner traversal,
checkpoint semantics, MariaDB ownership and source-file safety are unchanged.
