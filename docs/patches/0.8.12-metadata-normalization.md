# 0.8.12 metadata normalization and tag mapping

Version 0.8.12 closes the verified legacy tag-translation/combination gap without
reviving the old free-form metadata model. Schema 9 stores database-global custom
overrides while the built-in mapping in `metadata_mapping.py` preserves 0.8.11
canonical metadata behavior by default.

Supported raw sources are EXIF, embedded XMP and optional IPTC. Custom rules map
only to an allowlisted canonical field set: capture date, camera make/model,
rating, keywords, caption and country/state/city/sublocation. One override may
redirect a built-in source tag, or use an empty target to suppress a built-in
mapping. Several raw tags can feed one canonical target. Scalar targets use the
lowest successful priority; keywords combine all mapped values in priority order.
XMP namespace prefixes are treated as producer aliases, so rules persist the
property local name.

Mappings are catalogue data rather than local Kodi settings. That keeps shared
MariaDB clients consistent. The **Metadata mapping** browser edits custom overrides
only; resetting the list restores built-in behavior. A mapping change never edits
source files and never starts a scan automatically.

Schema 9 also adds `pictures.metadata_index_hash`. It hashes the effective mapping
and metadata extraction settings, and participates in scan-checkpoint compatibility.
An unchanged picture is reused only when size, mtime and this fingerprint match.
Existing schema-8 rows intentionally have a null hash, so the first post-upgrade
scan re-reads picture metadata once and rebuilds derived search data. Later
unchanged scans become incremental again.

Safety and compatibility notes:

- Query Model remains version 1; saved query JSON is unchanged.
- SQLite and MySQL/MariaDB use equivalent schema-9 structures.
- SQLite keeps the normal verified pre-migration backup; MariaDB migration is
  covered by an opt-in schema-8-to-9 integration test.
- GPS coordinates, image dimensions and EXIF orientation keep their dedicated
  extraction paths and are not custom mapping targets in this release.
- Screensaver, repository and Estuary runtime revisions do not change.
- No original media, XMP/IPTC/EXIF payload or playlist file is modified.
