# 0.2.41 mixed-playlist probe and start guard

## Runtime evidence

Kodi 21.3 on Windows accepted a one-picture picture-playlist probe and exposed
the expected item through the picture player. After MyPicsDB added the real
picture-and-video list, however, Kodi opened every JPEG through `VideoPlayer`
as a one-frame MJPEG stream. The cached `compatible` result then made later
starts skip the probe entirely. The same log also showed two slow SMB playlist
builds overlapping and writing to the same global Kodi picture playlist.

## Change

The compatibility probe now contains one known picture and one known video, so
it exercises the same mixed-media route as the real slideshow. After the full
playlist opens, MyPicsDB verifies the expected starting picture again before it
caches the route as compatible. An exact video-player match clears the list and
uses the existing native recursive album fallback.

A session-local Home-window property guards playlist construction. A second
slideshow action selected while another action is still preparing a list is
rejected with a notification instead of clearing or appending to the shared
Kodi playlists. The property has a short expiry so an interrupted plug-in
request cannot block the rest of the Kodi session indefinitely.

Database schema 5 and repository add-on 0.2.26 are unchanged.
