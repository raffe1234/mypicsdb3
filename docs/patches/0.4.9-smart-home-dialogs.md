# 0.4.9 smart home providers and editor actions

Kodi 21 reported `unmatched parentheses` while resolving smart home rows and
then called the saved-search route with values such as `home_smart_id_8)`. The
Estuary fragment had embedded `Addon.SettingInt(addon_id,setting_id)` inside a
`$INFO[...]` URL. The commas belonging to the nested info label were interpreted
as `$INFO` prefix/suffix separators.

MyPicsDB 3 now publishes each materialized home slot as simple Home-window
properties. Built-in row visibility, smart row mode and headings read those
properties. Smart content paths use the fixed route `home-smart?slot=N`; the
plug-in validates the slot and resolves its saved-search ID. Invalid or empty
slots return an empty provider instead of raising a Python exception.

The release also adds a reusable XML action-list dialog. **Configure home-screen
rows** displays only row entries and **Add smart collection** in its scrolling
list, with **Cancel**, **Save** and **Defaults** on the right. The Smart filter
editor keeps **Cancel** and **Save smart collection** in the same persistent
area. Native select-dialog fallbacks omit explicit Cancel rows because Kodi
already supplies a Cancel button.

The plug-in advances to 0.4.9. Generated Estuary revisions advance to 14 for
Kodi 21 Omega and 12 for Kodi 22 Piers. Database schema 5 and repository add-on
version 0.2.26 are unchanged, and no catalogue rescan is required.
