# 0.8.38 — Refresh-failure diagnostics and filtered log export

Version 0.8.38 is a diagnostic release for the remaining one-picture **Refresh
metadata** failure reported in issue #20. It deliberately does not change EXIF,
XMP, IPTC normalization, the database schema or the metadata extractor revision.

## Phase-aware refresh failure logging

Unexpected failures in one-picture **Refresh metadata** now record the current
refresh phase, exception type and source site in the MyPicsDB 3 log entry. The
phases distinguish lock acquisition/release, source stat, fresh metadata
extraction, location-cache access, catalogue write and folder-summary work.

The failure record is intentionally narrow. It does not include the picture
filename, source URI, GPS values or embedded metadata. This makes one reproduced
failure substantially more useful without adding another parser change before the
remaining failure has been identified.

## Export MyPicsDB 3 log

**Diagnostics > Export MyPicsDB 3 log** asks the user for a writable destination
and creates a timestamped text file containing only lines with the `[MyPicsDB 3]`
marker from:

- `special://logpath/kodi.old.log`;
- `special://logpath/kodi.log`.

Reading both files preserves evidence from the previous Kodi session when the
application has been restarted. Each source read is bounded to its final 16 MiB;
an incomplete first line is discarded if a bounded tail was needed.

The export is intentionally separate from the existing privacy-safe support bundle.
Users are reminded to review the text file before sharing because older MyPicsDB 3
log messages may contain filenames or source information.

## Compatibility and upgrade impact

- database schema remains 9;
- Query Model remains 1;
- metadata extractor revision remains 2;
- repository add-on remains 0.2.26;
- screensaver remains 0.7.0;
- source media remains read-only;
- no full-library rescan is required.
