# 0.8.18 — Random Home session diversity

## Problem

Since 0.4.5, random Home providers deliberately derive a deterministic database
pivot from their provider generations. That prevents Kodi from showing a
different set every time it re-queries an unchanged Home row.

The generation counters are session-local Home-window properties. After a Kodi
restart they can begin at the same values again, which made Random memories,
Random albums and On this day - random start from the same deterministic pivot
as an earlier Kodi session. With a large catalogue this could make a small set
of pictures appear much more often than expected.

## Change

MyPicsDB 3 now publishes one random UUID token in
`MyPicsDB3.RandomWidgetSessionV1` for the current Kodi session. Random Home
provider seeds include:

- route;
- the session token;
- normal Home generation;
- random Home generation.

The token is created lazily and stored in the Home window, so separate Kodi
Python interpreters converge on the same session value. A new Kodi session gets
new entropy, while repeated provider queries in the same session remain stable.

## Performance and compatibility

The database query strategy is unchanged: pictures and folders still use their
indexed stored `random_key` and a bounded pivot query. The patch does not add
`ORDER BY RANDOM()` / `RAND()`, does not scan source media and does not rewrite
existing random keys.
