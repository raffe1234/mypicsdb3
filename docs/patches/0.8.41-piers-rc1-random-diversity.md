## Baseline and scope

- Based on the supplied `de765f952fc642138d611c839a7be05f58e3d6d0`
  0.8.40 snapshot and the V26 handover dated 2026-10-29.
- **No speculative Kodi API rewrite.** `contrib/estuary/upstream.json` already

  RC1 release notes, but a real-device smoke test is still mandatory.

## Random-selection rationale

Before this patch, large random picture lists came from **one contiguous run**
through the precomputed, indexed `random_key` ordering. This is fast but
produces tightly correlated batches when two pivot positions are close. In
addition, after playing every screen-saver picture, `default.py` shuffled and
replayed the **same list** indefinitely, even if the collection contained
150,000 pictures.

For random queries requesting at least 48 pictures, this patch splits the batch
between at most four evenly distributed, randomly offset key ranges. It keeps
existing indexed seek + wraparound + `LIMIT` reads; no `ORDER BY RANDOM()` or
full-table shuffle is introduced. A seeded Home widget remains deterministic
within a generation. De-duplication and a bounded fallback query preserve small
collection coverage. Smaller random queries, album random selection, On This Day
random, and ordered collection browsing remain unchanged.

The screensaver requests a fresh random collection batch only after all images
in its current batch were shown. Failure to get a new batch falls back to
shuffling the existing set, and ordered mode is not changed. The random queries
also refer directly to non-null `p.random_key`, allowing existing key indexes
to be considered by the database planner (rather than wrapping it in COALESCE).

Neither this algorithm nor any random algorithm can guarantee that a picture
will never repeat across independent selections. Large-scale history tracking
was intentionally deferred to avoid profile writes and unbounded memory use.

## Versioning and safety

- Picture add-on / Python package: 0.8.41.
- Screensaver: 0.7.1, requiring the compatible 0.8.41 picture add-on.
- Repository add-on: unchanged 0.2.26.
- Schema: unchanged 9; no migration, reindex, full catalogue scan or source
  media write.
- Skin pins and patch revisions: unchanged. No new skin ZIP is claimed to have
  been built unless the official upstream archive is accessible.

## Acceptance on Kodi 21 and Kodi 22 RC1

1. Confirm correct 0.8.41 / 0.7.1 installation and the Piers RC1 skin package;
   verify browsing, still/video tiles, image metadata (especially non-midnight
   capture times), fullscreen display, Home widgets and source scanning.
2. Open Random memories multiple times without refreshing; verify same Home
   generation stays stable. Refresh random selections; verify it changes.
3. Select a manual or smart collection with many pictures; set the screensaver
   random on and a small batch (e.g. 50). Observe more than one batch and check
   that newly shown pictures can come from across the collection, not just the
   first set again. Repeat with random off and confirm collection order.
4. Verify a small collection, unavailable SQLite or SMB media, cancellation,
   and screensaver start/stop. Ensure there are no error loops or source writes.
5. If MariaDB is used, verify SELECT-only behaviour, latency and both clients.
   Monitor query time/locks for 4-window selections before release.
6. Run Actions CI and MariaDB workflows on the exact pushed commit before
   tagging; avoid treating local Python tests as a real Kodi runtime pass.
