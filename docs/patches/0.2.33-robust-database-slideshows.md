# MyPicsDB 3 0.2.33: robust database slideshows

## Problem

Database-backed views such as recent media, dates, search results, favorites and
ratings can contain thousands of items from unrelated folders. MyPicsDB 3 sent
the complete result, up to 5,000 paths, in one `Playlist.Add` JSON-RPC request.
That produced a large synchronous payload, kept the mixed-video monitor armed
while Kodi was still constructing the playlist and left a partially populated
picture playlist behind if a later operation failed.

Rows with missing or duplicate URIs could also shift the position selected by
**Play slideshow from here**.

## Change

- Add database playlist items in batches of 250 while preserving catalogue
  order.
- Ignore empty and exact duplicate URIs before playback.
- Recalculate the requested start position after that cleanup.
- Keep the mixed-video monitor inactive during playlist construction and arm it
  only after `Player.Open` succeeds.
- Clear the partially built picture playlist if a batch or the final open call
  fails.
- Convert direct Kodi JSON-RPC transport failures into the existing
  `SlideshowError` path so the user receives the normal slideshow error
  notification instead of a raw plug-in failure.

## Compatibility

- Native recursive album slideshows introduced in 0.2.28 are unchanged.
- Database query order, filters and the 5,000-item action limit are unchanged.
- Database schema remains version 4.
- Original pictures and videos are never modified.
- Repository add-on version remains independent and unchanged.

## Verification

Automated coverage checks:

- small playlists retain their order and selected start position;
- empty and duplicate paths are removed;
- a playlist larger than one batch uses multiple ordered `Playlist.Add` calls;
- a failed later batch clears the partial playlist;
- direct JSON-RPC transport errors use the controlled slideshow error path;
- a multi-folder mixed result recalculates its start position and arms the video
  monitor only after successful playback.

Manual Kodi testing should cover recent/search results containing media from
several SMB folders, a result larger than 250 items and **Play slideshow from
here** near the middle of the result.
