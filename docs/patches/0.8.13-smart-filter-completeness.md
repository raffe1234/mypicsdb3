# 0.8.13 smart-filter completeness and Needs attention

Version 0.8.13 completes the next legacy-parity step without changing database
schema 9 or Query Model version 1.

The Kodi smart-filter editor now exposes more of the operators already validated
by Query Model v1. Equality-style fields can offer **Is** / **Is not**; the
negative form is represented as a one-child Query Model group with
`negated=true`, so no `neq` SQL operator or raw-SQL path is added. Date, rating,
camera, keyword, MIME and canonical location fields expose **Exists** /
**Missing** where the model already supports `is_not_null` / `is_null`. Rating
also supports exact, lower-bound, upper-bound and inclusive-range matching.
MIME type is now selectable using the same bounded facet-count API as extension
and stored location values.

A new **Needs attention** main-menu view provides live presets for:

- pictures without capture date;
- pictures without camera metadata;
- pictures without any canonical country/state/city/sublocation value;
- pictures without keywords.

The presets are ordinary validated `PictureQuery` objects. Counts use
`Catalog.count_query_pictures()` and result pages use `Catalog.query_pictures()`.
They select pictures rather than videos, exclude rows marked missing, follow the
normal minimum-rating display policy and never start a scan or write metadata.

Compatibility and safety notes:

- plugin version advances to 0.8.13;
- database schema remains 9;
- Query Model version remains 1 and existing saved version-1 JSON stays valid;
- no source file is copied, moved, deleted or rewritten;
- no Estuary runtime file changes, so generated skin revisions do not advance;
- screensaver and repository add-on versions remain unchanged.
