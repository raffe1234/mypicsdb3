# 0.8.8 Home startup architecture

Kodi can load Estuary `Home.xml` before the MyPicsDB 3 background service starts. Since 0.4.10 the service deliberately delays Home-window property writes for five abortable seconds after its own startup to avoid an in-place update race. The previous skin fragment also used those session-local properties as `<include condition>` values, so a cold Home load could permanently omit MyPicsDB controls until the skin was reloaded.

Version 0.8.8 removes that dependency. The Estuary fragment always materializes nine MyPicsDB poster slots. Runtime visibility reads the persistent `home_row_N` add-on setting, and each slot points to `home-slot?slot=N`. The plug-in resolves that slot to the current built-in view, smart collection or manual collection when Kodi requests the provider.

`MyPicsDB3.HomeWidgetGeneration` remains in provider URLs for normal invalidation. A per-slot skin variable includes `MyPicsDB3.RandomWidgetGeneration` only when that slot currently contains Random memories, Random albums or On this day - random, preserving selective random refresh. A companion per-slot browse-mode variable also keeps the three random providers at `browse=never`. Smart/manual heading properties remain supplemental and can arrive after Home has loaded.

Saving the Home layout now increments the provider generation without `ReloadSkin()`. Database schema remains 7.
