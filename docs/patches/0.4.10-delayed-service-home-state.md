# 0.4.10 delayed service Home-state publication

## Problem

A Kodi freeze was observed immediately after installing 0.4.9 while the active
MyPicsDB 3 Estuary skin was being unloaded and the newly restarted background
service was starting. The available crash material does not contain a usable
native stack trace, so the exact Kodi-side cause cannot be proven. The timing
identified one new startup behaviour worth removing: the service constructor
published all Home-row properties immediately, before Kodi had completed the
in-place update.

## Change

The service creates `KodiContext` with automatic Home-state publication disabled.
After the service-start log entry it waits five seconds with
`Monitor.waitForAbort()`. If Kodi requests shutdown, the service exits without
publishing or entering `ServiceLoop`. Otherwise it enables publication, writes
the widget limit and row-slot properties once, and continues normally.

Plug-in requests keep the default immediate behaviour. Editor saves and widget
invalidations therefore remain responsive.

## Compatibility

The plug-in advances to 0.4.10. Database schema 5, generated Estuary revisions
14/12 and repository add-on version 0.2.26 are unchanged. No rescan, database
migration or skin reinstall is required.
