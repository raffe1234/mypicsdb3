# 0.6.0 picture quality and collection UX follow-up

## Older JPEG quality

A real Kodi 21 Windows comparison showed that one 2048x1536 JPEG looked sharp
when opened through Kodi **Media sources**, but very soft in the MyPicsDB Home
row and after `ShowPicture` was invoked from that row. The source file itself was
unchanged. MyPicsDB had been wrapping still artwork in an explicit `image://`
texture URI, while Kodi's native file browser uses the media path.

Still pictures now publish the original picture/thumbnail URI directly as their
artwork. Kodi remains responsible for normal texture caching. Generated video
frames keep `image://video@...`, and an explicit still thumbnail attached to a
video keeps the existing canonical image wrapper. No catalogue rescan is needed.
Existing stale Kodi texture-cache entries may disappear only after the new art
key is requested; restarting Kodi after installing the build is sufficient for
the acceptance test.

## Home collection access

Picture and video items already expose **Add to collection** through their
plug-in context menu. Home widget items now also expose **Open Collections**,
which opens the MyPicsDB manual-collection browser without first navigating
through the add-on root. Kodi's native full-screen picture viewer does not keep
the originating plug-in context menu, so adding a dedicated full-screen action
is deliberately left for a later viewer-integration change rather than replacing
the stable native picture viewer in this release.

## Music playlist picker

The first 0.6.0 build opened `Dialog.browseSingle()` at Kodi's complete music
source root. That made the user search among drives, add-ons and every configured
music source before finding saved playlist files. With no existing assignment,
the picker now starts at:

```text
special://profile/playlists/music/
```

On Windows that normally maps below:

```text
%APPDATA%\Kodi\userdata\playlists\music\
```

An existing assignment remains the picker default, and users can navigate to a
different music source when the playlist lives elsewhere. Supported extensions
are unchanged.

## Compatibility

The add-on remains version 0.6.0 and catalogue schema 7. No database migration,
backup or source rescan is required.
