# 0.8.39 — EXIF diagnostics use raw tag values

Issue #20 produced a repeatable asymmetry: normal scanner-style metadata extraction
could succeed while Metadata diagnostics failed with
`TypeError: 'NoneType' object is not callable`. Individual Refresh metadata uses the
same diagnostics-enabled extraction path.

The difference was diagnostics-only formatting in `metadata.py`: `_tag_text()` called
`str()` on the ExifRead tag wrapper for Make, Model and GPS reference fields, while
normal metadata mapping reads the wrapper's raw `values`. A tag wrapper with unusable
printable/string behaviour could therefore fail only when diagnostics were requested.

0.8.39 makes `_tag_text()` consume the same raw tag values, unwrap a single list/tuple
value and treat diagnostic text-conversion failure as an empty diagnostic display
value rather than an extraction failure. A regression test reproduces the exact
`NoneType` callable exception while proving normal and diagnostics-enabled extraction
both retain the usable camera values.

This is a compatibility/diagnostics fix only. Schema 9, Query Model 1, metadata
extractor revision 2, source-file read-only behaviour and metadata precedence remain
unchanged. No automatic or full-library reindex is required.
