# 0.8.39 — EXIF diagnostics use raw tag values

Issue #20 produced a repeatable asymmetry: normal scanner-style metadata extraction
could succeed while Metadata diagnostics failed with
`TypeError: 'NoneType' object is not callable`. Individual Refresh metadata uses the
same diagnostics-enabled extraction path.

The difference was diagnostics-only formatting in `metadata.py`: `_tag_text()` called
`str()` on the ExifRead tag wrapper for Make, Model and GPS reference fields, while
normal metadata mapping reads the wrapper's raw `values`. A tag wrapper with unusable
printable/string behaviour could therefore fail only when diagnostics were requested.

0.8.39 makes `_tag_text()` consume the same raw tag values, unwrap a single list/tuple
value and treat diagnostic text-conversion failure as an empty diagnostic display
value rather than an extraction failure. A regression test reproduces the exact
`NoneType` callable exception while proving normal and diagnostics-enabled extraction
both retain the usable camera values.

This is a compatibility/diagnostics fix only. Schema 9, Query Model 1, metadata
extractor revision 2, source-file read-only behaviour and metadata precedence remain
unchanged. No automatic or full-library reindex is required.


## Debug observability added before release

Because issue #20 required several external log rounds, 0.8.39 also makes future
metadata failures more self-locating when **Debug logging** is enabled. The fresh
extractor updates a small in-memory `stage` marker as it crosses prefix I/O, dimension
probing, EXIF, diagnostics-only EXIF formatting, XMP, IPTC, mapping, GPS finalization
and metadata hashing. If extraction escapes with an unexpected exception, the log can
therefore show both the outer operation phase and the last extractor stage, for example
`phase=metadata-extraction extract_stage=iptc-read`, plus exception type and source
site.

Successful diagnostics/refresh reads emit one structural summary containing parser
availability/tag counts, fallback use, buffered header-byte count, XMP/IPTC state and
GPS source. Error details are reduced to exception *types*. Filenames, source URIs,
GPS values, camera/caption/location values and embedded metadata are not included.

Debug logging also gains a safe runtime environment line and scan start/plan/per-source
summary lines, plus a privacy-safe per-media scan failure phase/type record. It does
not add one success line per scanned media file and does not log SQL parameters or
database credentials.
