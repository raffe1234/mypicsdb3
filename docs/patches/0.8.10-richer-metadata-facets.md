# 0.8.10 richer metadata facets

Version 0.8.10 extends the existing Query Model version 1 instead of adding
special SQL paths for smart collections. The additions are backward-compatible:
existing saved version-1 JSON remains valid and database schema 7 is unchanged.

New allowlisted criteria cover file extension, MIME type, stored country,
state/region, city, sublocation and image shape. Date, camera and keyword rules
also gain presence/absence operators for future consumers. Extension and MIME
values are normalized; every SQL comparison still uses compiler-owned fragments
and bound parameters.

`Catalog.query_facet_counts()` provides bounded counts for scalar metadata
facets by reusing the same compiled query selection. The Kodi smart-filter
editor uses those counts for file extensions and stored location values, and
adds landscape, portrait and square shape choices. Aspect classification swaps
width/height for EXIF orientations 5-8 before comparing them.

Safety and compatibility notes:

- no database migration or rescan is required;
- no source files or embedded metadata are modified;
- no widget or Home provider behavior changes;
- no Estuary runtime code changes, so skin revisions do not advance;
- facet fields are selected through a fixed allowlist, never a user-provided SQL
  identifier or expression;
- facet limits are bounded and the current rating/missing/scope policy remains
  part of the compiled query selection.
