# 0.5.0 native collection picture slideshow

## Symptom

On Kodi 21.3 for Windows, choosing **Play picture slideshow** for a manual
collection could leave Kodi's busy spinner flashing until the application was
terminated. The log showed the same JPEG repeatedly entering
``VideoPlayer::OpenFile`` after JSON-RPC had populated and opened picture
playlist 2.

## Cause

The first collection safety patch separated mixed collections into pictures or
videos, but the picture branch still used the JSON-RPC picture playlist. On the
affected Kodi build, even a picture-only collection playlist was routed through
VideoPlayer and immediately reopened after end-of-file.

## Fix

- Add a hidden ``slideshow/collection-pictures`` route that returns only still
  image URLs from the collection.
- Prefix hidden item labels with their zero-padded stored position so Kodi's
  directory-label sort retains collection order. Visible picture metadata keeps
  the normal filename.
- Start Kodi's native ``SlideShow`` built-in on that plug-in directory and pass
  the selected media URI through ``beginslide`` for **Play slideshow from here**.
- Keep collection videos on Kodi's video playlist.
- Continue filtering empty paths, duplicates, missing media, rating-hidden media
  and videos from the native picture route.

No schema, scan or version-number change is required because 0.5.0 has not yet
been tagged.

## Runtime acceptance

1. Open a mixed collection and choose **Play picture slideshow**.
2. Confirm Kodi enters its native picture window without a flashing busy spinner.
3. Leave a one-picture slideshow open for at least 30 seconds and confirm the
   JPEG is not repeatedly reopened.
4. Test a picture-only collection containing at least three pictures whose file
   names are not alphabetically aligned with collection order.
5. Test **Play slideshow from here** on the second or third picture.
6. Return to the mixed collection and confirm **Play video playlist** still works.
7. Confirm the log contains ``route=native-collection-picture`` and does not
   repeatedly contain ``VideoPlayer::OpenFile`` for the same JPEG.
