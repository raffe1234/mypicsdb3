# 0.8.40 — preserve picture times in Kodi

The catalogue stores timestamps as `YYYY-MM-DD HH:MM:SS`. Passing that string
unchanged to `InfoTagPicture.setDateTimeTaken()` loses the time of day: Kodi's
W3C parser splits on `T`, so a space-separated timestamp is read as a date with
midnight as its time. This was checked in the Omega and Piers implementations,
including the pinned 21.3-Omega and 22.0b2-Piers releases.

Convert the first space to `T` only at the picture InfoTag boundary in
`PluginUI._set_picture_info()`. Both ordinary listings and native slideshow
directories use this helper. Already formatted W3C timestamps, date-only values
and explicit offsets are preserved. No timezone is inferred or added. Fractional
seconds are passed through; Kodi's parser uses whole seconds.

The database, MyPicsDB3.TakenAt property, video date-added API, legacy fallback,
metadata extraction, public URLs and scan state are not changed. Schema remains
9, Query Model 1 and extractor revision 2. No rescan is needed.

The parameterized regression covers 24 combinations: two directory paths,
taken/discovered dates, and six timestamp cases. With the old implementation,
eight SQL-format cases fail and sixteen other cases pass. All pass with the fix.
The test double rejects a space separator; it does not execute Kodi's C++ parser.
