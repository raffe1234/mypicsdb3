# 0.2.45 scan control and progress

Version 0.2.45 publishes the active scan through session-local Kodi Home-window
properties. This lets the background service and plug-in menu share progress
without adding database schema or persistent-profile state.

While a scan owns the catalogue lock, **Scan now** is replaced by **Stop scan**.
The stop action requires confirmation and writes a token-specific cancellation
request. The scanner checks that request at existing filesystem, metadata and
catalogue checkpoints, commits already completed work and records the active
source scan as `cancelled`.

Manual and scheduled scans both publish the current source, path and discovered
media count. Scheduled scans also create Kodi's non-modal background progress
dialog. GUI updates are throttled to at most twice per second, with every
hundredth discovered item allowed through, so large libraries do not generate a
GUI call for every file.

A scheduled scan that finds the catalogue scan lock occupied is now logged as
skipped rather than failed. The patch also completes malformed `folder` routes
without an `id` parameter instead of allowing a `KeyError` to escape.

Database schema 5, Query Model version 1, NEF/Libraw behavior and repository
add-on version 0.2.26 are unchanged.
