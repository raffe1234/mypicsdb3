# MyPicsDB 3 0.2.38: logging and metadata hygiene

## Reason

External 0.2.37 testing completed picture-only, mixed, Videos-node and
back-and-forth slideshow scenarios without a Kodi crash. The remaining report
was diagnostic: no visible MyPicsDB debug lines, repeated Kodi core attempts to
load MP4 entries as slideshow images, an empty UPnP object-id warning and a
deprecation warning for video metadata set through `ListItem.setInfo`.

The repeated `Error loading the current image` lines are emitted by Kodi's
picture window while a video entry is present in picture playlist 2. Because
playback and transitions now complete, this release deliberately does not
replace the mixed-slideshow state machine merely to suppress core log noise.

## Changes

- Slideshow route selection and privacy-safe counts are INFO messages for every
  start, independent of the add-on Debug logging switch.
- Advanced settings include **Write diagnostic log entry**. It writes the
  installed version and the current Debug logging value without database access.
- Video list items use `InfoTagVideo.setTitle` and `setDateAdded` when available.
- The mixed-slideshow completion message no longer contains the media URI.

## Kodi checks

1. Open MyPicsDB 3 settings, enable Advanced settings visibility if necessary,
   and press **Write diagnostic log entry**.
2. Confirm a line such as `[MyPicsDB 3] Diagnostic log entry: version=0.2.38
   debug_logging=true` in the active `kodi.log`.
3. Start a picture-only album and a mixed album. Confirm the INFO route lines.
4. Confirm mixed picture → video → picture playback and manual stop still work.
5. Confirm Kodi no longer reports the video `ListItem.setInfo` deprecation from
   MyPicsDB 3.

The UPnP empty object-id warning and Kodi's MP4-as-image errors should still be
correlated with actual playback failure before any larger player redesign.
