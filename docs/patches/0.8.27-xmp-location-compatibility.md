# 0.8.27 XMP location compatibility and bounded JPEG metadata I/O

Version 0.8.27 follows the 0.8.26 Kodi VFS byte-stream fix with a narrow
metadata-compatibility and diagnostics patch.

## Behaviour

- EXIF remains the preferred source for GPS coordinates. When no EXIF coordinate pair
  is available, common XMP `GPSLatitude` / `GPSLongitude` representations can be
  normalized locally.
- Common IPTC Extension `LocationShown*` and `LocationCreated*` aliases can fill
  otherwise-empty canonical city, state/region, country and sublocation values.
- Metadata diagnostics shows raw XMP GPS values, the final GPS source and up to a
  bounded set of matched XMP location/GPS property names. Nothing is sent to a map or
  geocoding provider.
- JPEG metadata-prefix acquisition walks marker headers through Start Of Scan, reads
  only APP1 (EXIF/XMP) and SOF payloads and seeks over unrelated APP/compressed data.
- A Refresh metadata request blocked by a catalogue scan, migration or another refresh
  shows an explicit modal explanation and is not queued.

## Compatibility and safety

Existing catalogue rows are not automatically rewritten on upgrade. Use Metadata
diagnostics first and explicit Refresh metadata after Fresh extraction sees the values
you want to index. Source files remain read-only; refresh/scanning remain serial.
Database schema stays at 9 and Query Model stays at version 1. No Estuary change is
required.
