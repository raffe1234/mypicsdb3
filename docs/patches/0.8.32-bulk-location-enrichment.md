# 0.8.32 — explicit bulk location enrichment

## Goal

Make **Browse metadata > Location** useful for large GPS-tagged libraries whose files
contain coordinates but no embedded country/state/city/sublocation text, without making
scanner or metadata-refresh paths perform implicit network requests.

## Behaviour

- Adds local-only **Analyze GPS coverage** to the Location metadata category. It reports
  **stored/indexed** GPS coverage, named-location completeness, exact and bucketed
  coordinate counts, existing cache reuse, predicted same-run bulk reuse, estimated
  online lookups and public-Nominatim throttle time without network I/O, source-file reads
  or catalogue writes.
- Makes the planning report verify the current metadata fingerprint. It shows whether
  **Store GPS coordinates** is enabled, how many rows were indexed with the current
  metadata settings/extractor revision and how many require metadata refresh before GPS
  coverage can be considered complete. This avoids interpreting an old privacy-gated or
  pre-extractor-fix catalogue as if it were a fresh scan of the originals.
- Adds an explicit code-level metadata extractor revision to `metadata_index_hash`. Parser
  or VFS fixes that can change normalized EXIF/XMP/IPTC/GPS values now invalidate stale
  rows even when source size/mtime, metadata settings and mappings are unchanged.
- Adds **Resolve missing locations from GPS** to the Location metadata category.
- Processes only indexed still pictures with stored GPS and at least one missing named
  location field.
- Runs serially under the existing `location-enrichment` catalogue lock.
- Publishes background progress and exposes **Stop location lookup** from another Kodi
  plug-in invocation.
- Stores a stable picture-ID horizon and resumable checkpoint in schema-9 `meta`.
- Reuses per-picture enrichment, exact provider cache and a bulk-only four-decimal
  coordinate cache before network I/O.
- Sends only latitude/longitude to the configured Nominatim-compatible endpoint.
- Writes named location with `fill_only=True`; embedded EXIF/XMP/IPTC values remain
  authoritative.

## Public Nominatim policy guard

The default public endpoint remains one thread with persistent caching. New misses are
spaced by at least 1.1 seconds. When the same saved run has aged beyond 24 hours, the
minimum interval becomes 15.1 seconds (about four requests per minute). Kodi warns that
very large libraries should use an operator-controlled compatible endpoint.

## Compatibility

- database schema: unchanged at 9;
- Query Model: unchanged at 1;
- repository add-on: unchanged at 0.2.26;
- screensaver: unchanged at 0.7.0;
- source files: read-only;
- scanner and whole-library metadata refresh: no online geocoding added.
