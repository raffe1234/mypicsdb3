# 0.8.35 — XMP description caption handling

## Purpose

Correct picture captions when JPEG XMP contains a normal RDF `Description` wrapper
and a real description property such as `dc:description`. Some files could previously
produce a caption containing unrelated XMP values such as category, country or
headline instead of the full description.

## Cause

The XMP helper matched XML elements by local name. A request for `Description` could
therefore match the structural `rdf:Description` container. At the same time, metadata
mapping keys are case-insensitive, so the duplicate built-in `Description` rule could
replace the intended built-in `description` rule.

## Behaviour

- Keep the built-in `xmp / description -> caption` mapping and remove the duplicate
  uppercase built-in rule.
- Detect the namespace prefix bound to the RDF namespace and exclude RDF structural
  `Description` elements and attributes from property lookups. The fix is
  prefix-independent; producers do not have to use the literal `rdf` prefix.
- Preserve custom mappings for a genuine non-RDF property named `Description`.
- Keep IPTC `caption/abstract` at its existing higher mapping priority when IPTC is
  available.
- Increment the metadata extractor revision from 1 to 2. Existing unchanged files
  therefore receive a changed metadata-index fingerprint and are eligible for
  re-extraction during a normal scan or **Refresh all picture metadata**.
- Do not change database schema 9, Query Model version 1, repository add-on version
  or screensaver version. Source image files remain read-only.

## Validation

Regression tests cover both a standard `dc:description` nested inside an RDF
`Description` container and a custom uppercase `Description` property with a
nonstandard RDF namespace prefix. Run the normal repository test suite and
`tools/verify.py` before release.
