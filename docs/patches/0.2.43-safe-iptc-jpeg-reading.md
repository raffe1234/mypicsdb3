# 0.2.43 safe IPTC JPEG reading

Kodi 22 testing exposed two related metadata problems. `IPTCInfo` supports
indexed field access but does not inherit the dictionary `get()` method used by
MyPicsDB 3, so every JPEG with IPTC reading enabled could fail with
`'IPTCInfo' object has no attribute 'get'`.

Version 0.2.43 reads IPTC fields through a small indexed-access helper that
returns an empty value for missing fields. It also sends only JPEG candidates to
IPTCInfo3. When the metadata prefix is available, the JPEG signature is the
source of truth; MIME type and filename are fallbacks only when the prefix could
not be read. PNG, HEIC and other image formats therefore no longer produce
`File not a JPEG, trying blindScan` messages during normal scanning.

This patch does not change the database schema, the Query Model, slideshow
routing, Kodi view-mode handling or the repository add-on version.
