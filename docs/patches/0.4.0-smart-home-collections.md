# 0.4.0 live home limits and smart collection rows

Version 0.4.0 completes the next step after the 0.3.0 smart-filter editor: a
saved smart collection can be used as a Pictures-home content provider.

## Why 39 still displayed ten

The 0.3.5 setting accepted 4–40, but Estuary's content path did not change when
the saved value changed. Kodi could therefore keep the already resolved ten-item
provider. The plug-in also capped a URL limit against its local settings
snapshot, which could briefly remain at ten in a long-running interpreter.

The 0.4.0 Estuary fragment includes both values in every MyPicsDB 3 home URL:

```text
limit=$INFO[Addon.SettingInt(plugin.image.mypicsdb3,home_widget_limit)]
generation=$INFO[Window(Home).Property(MyPicsDB3.HomeWidgetGeneration)]
```

The service increments the generation when the setting changes and after a scan
changes catalogue rows. The plug-in honours the explicit home value directly,
clamped to 4–40. No complete `ReloadSkin()` is needed for an ordinary limit or
catalogue update.

## Smart rows

**Configure home-screen rows** now manages built-in and saved smart rows in one
ordered list. A saved collection can be added once, moved, enabled or disabled,
shown as Poster/Square/Wide, or removed from the home screen without deleting
the collection itself. Up to nine rows can be visible.

The layout is stored as versioned JSON in `home_layout_v2` and materialized to
nine hidden skin slots. This keeps the skin XML declarative while preserving a
flexible editor. Legacy built-in layouts migrate automatically. Deleted saved
searches are removed and renamed searches update their row heading.

Each smart provider URL contains only the saved-search database ID. The stored
Query Model is validated and rerun when Kodi requests the row, so newly scanned
matching pictures or videos can appear without editing the layout.

Database schema 5 and Query Model version 1 are unchanged. No rescan or database
migration is required.
