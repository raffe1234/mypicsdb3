# 0.3.4 scan cancellation and playback stability

Version 0.3.4 removes GUI refresh calls from the scan cancellation path. A
manual scan runs in a separate Kodi plug-in interpreter while the Pictures
window may still report that its container is updating. Refreshing that same
container from **Stop scan** or the scan's `finally` block can race Kodi's media
window and leave the interface unresponsive. Cancellation now only publishes
the token, lets the scanner stop at a safe checkpoint, closes the background
progress dialog and clears the shared scan state.

Manual and automatic scan progress is now playback-safe. The dialog is closed
before Live TV, a TV episode, movie, music item or other media becomes active.
If playback pauses are enabled, an already-running automatic scan waits at the
next cancellation checkpoint and resumes after playback. If pauses are disabled,
scanning may continue without any dialog or scan notification over the media.

The patch also hardens exceptional paths: progress-dialog failures no longer
abort a scan, scanner construction and unexpected runtime failures are reported
and cleaned up, notification/player calls tolerate Kodi shutdown, and the daily
standard-skin refresh is restricted to an active MyPicsDB 3 picture container.
No database or skin migration is required.
