# MyPicsDB 3 0.2.31: safe partial source scanning

## Problem

A source root could remain reachable while one nested SMB/NFS folder failed to
list. The scanner recorded the error and continued, but then treated the source
scan as complete and marked every unseen row as missing. A temporary failure in
one branch could therefore hide previously indexed media from that branch, and
could also affect other unseen paths before the next successful scan.

A listed file that temporarily failed `stat` or metadata access had a similar
risk: its existing catalogue row was not touched and could be marked missing at
the end of the scan.

## Change

- Any directory-listing failure marks that source traversal as incomplete.
- The scanner continues through readable folders and indexes their media.
- Missing-file and missing-folder marking is skipped for the entire source when
  traversal was incomplete.
- The scan run and source receive the explicit `partial` status.
- If a filename was listed but later access fails, an existing catalogue row is
  touched as seen so it remains active.
- A later complete scan resumes normal missing detection and marks genuine
  deletions.

The source-wide safety gate is intentionally conservative. A failed directory
may hide an arbitrarily large subtree, and preserving stale rows until a clean
scan is safer than interpreting an incomplete network traversal as deletion.

## Compatibility

- Database schema remains version 4.
- Repository add-on remains independently versioned.
- Original media is never modified.
- Successful scans and unavailable-root handling keep their existing behavior.
- Media access and metadata errors remain visible in scan status and logs.

## Verification

Automated coverage checks:

- a nested directory-listing failure does not mark rows missing;
- readable sibling folders still update during a partial scan;
- the scan is stored as `partial` with its error message;
- the next complete scan marks a genuine deletion;
- a listed existing file remains active when transient file access fails;
- normal complete scans retain their existing missing-file behavior.

Manual Kodi testing should include an SMB source where one nested share or
folder is temporarily unavailable, followed by a complete rescan after access
is restored.
