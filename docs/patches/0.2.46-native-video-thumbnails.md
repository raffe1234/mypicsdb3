# 0.2.46 native video thumbnails

Version 0.2.46 uses Kodi's built-in generated video image URI for indexed home
videos:

```text
image://video@<percent-encoded-media-uri>/
```

Kodi therefore extracts and caches a representative frame lazily when the item
is first displayed. MyPicsDB 3 does not run a separate FFmpeg process, does not
create a second thumbnail directory and does not add thumbnail work to the main
scanner. SMB, NFS, local and Unicode paths are encoded as a single URI component.

Explicit image artwork is retained when supplied. Legacy catalogue rows where a
video's `thumb_uri` points back to the video itself are converted at display
time, so no schema migration or full rescan is required. Newly scanned video
rows leave `thumb_uri` empty. The same rule is used for video-only folder and
date-group representative artwork.

A first preview can take a few seconds on network storage. Kodi owns generation
and texture-cache recovery; an isolated still-picture cache failure remains a
Kodi cache issue and does not cause MyPicsDB 3 to build a duplicate cache.
