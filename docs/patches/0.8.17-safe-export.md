# 0.8.17 — Safe export/copy + manifest

## Goal

Restore the useful low-risk part of legacy MyPicsDB export functionality without
reintroducing source-media mutation or an ad-hoc archive path.

## Delivered

- **Export current results** on global search, saved smart collections, Browse
  metadata and Needs attention.
- **Export collection** on manual collections.
- Complete ordered selection frozen to catalogue IDs before copying.
- COPY-only filesystem/VFS exporter with a unique dedicated destination folder.
- Destination refusal inside configured picture-source roots.
- Portable collision-safe filenames; no overwrite.
- Bounded 500-row catalogue metadata batches.
- Progress and cancellation that preserves already copied files.
- Version-1 JSON manifest with copied/missing/failed/collision summary and item
  provenance.
- Credential redaction for network/VFS URIs in manifests; copy-exception text is
  not persisted or logged.

## Deliberately not included

- no source move, rename, edit or delete;
- no destination overwrite mode;
- no ZIP/archive creation;
- no export resume state in the database;
- no schema change and no Query Model version change.

## Versions

- MyPicsDB 3: 0.8.17
- Database schema: 9
- Query Model: 1
- Screensaver/repository/Estuary runtime revisions: unchanged

## Verification focus

Exporter tests cover source immutability, folder/file collisions, partial
cancellation, missing media, destination-inside-source rejection, portable names
and VFS credential redaction. Catalogue/UI tests cover deterministic selection,
rating-policy forwarding and explicit export routes. The opt-in MariaDB test
exercises the new ordered selection/export metadata helpers against the shared
backend.
