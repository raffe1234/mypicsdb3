# 0.8.22 Location/GPS foundation

Version 0.8.22 modernizes the first safe part of the legacy map workflow without
introducing a network dependency.

Still-picture context menus now expose **Location details**. The action resolves
only the catalogue picture ID, then displays already-indexed canonical country,
state/region, city and sublocation fields. If **Store GPS coordinates** is enabled,
a validated latitude/longitude pair is shown locally to six decimal places. When
the setting is disabled, stored coordinates are deliberately hidden even if an old
row still contains them pending the next metadata reindex.

Pictures with normalized city or country metadata also expose **Browse this city**
and **Browse this country**. These actions reuse the existing curated Location
metadata browser and Query Model v1; they do not add a second query language or
raw SQL path.

`location.py` is the provider-neutral boundary for coordinate validation and local
formatting. It has no provider URL, API key, filesystem access or network I/O. A
future explicit **Open map** feature can consume this neutral representation, but
must require a deliberate user action before coordinates leave Kodi.

This release does not change database schema 9, Query Model version 1, scanner
concurrency, source files, Home providers or Estuary runtime revisions.
