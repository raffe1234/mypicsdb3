# MyPicsDB 3 0.2.35: stable Kodi view modes

## Scope

Kodi can return from `endOfDirectory` while the previous directory is still the
active container. MyPicsDB 3 previously sent `Container.SetViewMode` immediately
and once more after a fixed delay. During search navigation either command could
therefore change the parent add-on menu instead of the new picture result.

## Behaviour

The add-on waits for both `Container.PluginCategory` and `Container.Content` to
match the directory it just completed and remain stable for a short settling
period. Kodi formatting tags in category labels are ignored for comparison.

MyPicsDB then sends the configured view as a blocking built-in and verifies the
active picture-window view control. The target must remain active for 200 ms. If
Kodi performs a late path-specific restore to Shift or another remembered view,
MyPicsDB retries up to two more times, but only while the same category/content
pair remains active. Navigating away immediately cancels further view commands.

The total wait is bounded to two seconds. If Kodi never exposes the expected
container or cannot activate the configured view, MyPicsDB 3 stops without
touching another screen. Widgets, the root menu, Saved searches and other
file-list menus do not request an album view.

## Kodi checks

1. Set **Default album view** to Wall.
2. Keep the MyPicsDB 3 root menu in Wide list.
3. Open a text search and verify that the result uses Wall.
4. Return to the root menu and verify that it remains Wide list.
5. Repeat through **Saved searches** and **Open containing album**.
6. Confirm that home-screen widget layouts remain controlled by the skin.
