# 0.8.11 per-source scan policies

Version 0.8.11 closes a verified legacy-parity gap while keeping MyPicsDB 3's
modern scanner safety model. Old MyPicsDB source/root management supported
source-specific recursion and excluded paths. MyPicsDB 3 previously kept all
scan discovery rules in global Kodi settings.

Schema 8 adds `source_scan_policies`, keyed by `source_id`. A missing row means
**inherit global defaults**, so every existing installation keeps exactly the
0.8.10 behavior after migration. An explicit row stores a complete policy for:

- recursive traversal;
- include videos;
- picture extensions;
- video extensions;
- excluded path fragments;
- hidden-file/folder exclusion.

The Picture sources context menu now has **Source scan settings**. Users can
return a source to global defaults by deleting its override. Editing a policy
never scans automatically and never modifies source files.

The scanner resolves all effective policies before traversal begins. The local
resume-checkpoint signature includes those effective values per source in
addition to database identity and global metadata-reading settings. A changed
source policy therefore invalidates a checkpoint produced under different
recursion, media-type or exclusion rules.

Safety and compatibility notes:

- SQLite receives the normal verified pre-migration backup when upgrading 7→8;
- MariaDB/MySQL uses the same columns and application-level list serialization;
- the `recursive` policy identifier is quoted in SQL because `RECURSIVE` is reserved syntax in MariaDB/MySQL;
- no database-native JSON feature is required;
- policy rows cascade only when their source row is intentionally deleted;
- `@eaDir` remains an unconditional scanner exclusion;
- out-of-policy catalogue rows are only soft-marked missing after a complete
  successful scan and remain subject to the normal separate cleanup policy;
- Query Model remains version 1;
- screensaver, repository add-on and Estuary runtime versions are unchanged.
